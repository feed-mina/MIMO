0. 한 줄로 말하면

MIMO의 화면을 화장품 매장의 진열대처럼 편집할 수 있습니다. 먼저 진열 모양을 옮기고, 상품을 찾아오는 직원과 기록을 보관하는 창고를 연결하면 됩니다. 추측: 권고

확인: 오늘과 어제의 문서, 두 앱의 코드를 대조했습니다. 지금 완성한 것은 연결 방법과 샘플이며, 실제 서비스 연결은 아직 하지 않았습니다.

1. 그림으로 먼저 — 같은 매장, 서로 다른 역할

화면 편집기는 진열대를 배치하는 도구입니다. 진열대를 만들었다고 창고의 상품과 주문이 자동으로 연결되지는 않습니다. 비유의 한계: 실제 앱은 직원 대신 서버 프로그램이 검사하고 처리합니다.

4. 어디를 연결하나 — 진열대에서 창고로 가는 길

부품옮기는 방법추가로 필요한 것
상품 카드·소개 배너기존 카드·글자·사진 요소로 구성실제 상품을 읽어오는 연결
리뷰·장바구니입력칸과 버튼을 구성저장 후 다시 조회, 서버의 가격 검증
로그인·프로필폼과 프로필 모양 재사용로그인 확인 방식 연결
카메라·메이크업전용 기능으로 따로 연결촬영 권한·사진 처리 서버·실패 안내

확인: 현재 카메라 코드에는 먼저 정리할 부분이 있고, 연결 대상 서버의 구현은 저장소에서 확인되지 않았습니다. 그러므로 상품 화면부터 시작하는 편을 권합니다.

6. 숫자로 확인 — 숫자 옆에 뜻

숫자와 대상무슨 뜻인가
3가지 역할보여주는 화면, 처리하는 서버, 기록을 보관하는 저장소를 나눕니다.

0개 실제 API 연결이번 샘플은 외부 서버에 조회하거나 주문을 저장하지 않습니다.
0개 누락 파일샘플 가져오기 사전 검사에서 필요한 파일의 누락이 없었습니다.

확인: 파일 검사는 통과했습니다. 실제 로그인·상품 조회·주문·메이크업 성공을 확인한 것은 아닙니다.

7. 선택할 것 — 서버는 둘 다 가능합니다

선택어울리는 경우주의할 점
FastAPI파이썬을 익숙하게 쓰고 작은 기능부터 시작무거운 사진 처리는 별도 작업으로 분리
Spring Boot기존 자바 서버와 업무 체계가 있음화면과 주고받는 규칙을 먼저 맞추기
두 서버 함께주문 업무와 AI 처리를 따로 운영해야 함운영 부담 증가. 같은 주문을 양쪽에서 제각각 수정하지 않기

추측: 권고 · 기존 자바 서버가 없다면 FastAPI 하나로 상품 조회부터 시작하는 방법이 단순합니다. 이미 쓰는 서버가 있다면 그 서버를 유지해도 됩니다. 저장소를 바로 모두 바꾸는 것도 필수는 아닙니다.

중요한 구분

화면 조립 설명서는 “무엇을 어떻게 보여줄지”를 정합니다. 주고받는 데이터 규칙은 “어떤 값을 보내고 받을지”를 정합니다. 저장 구조는 “어떤 기록을 어떻게 연결할지”를 정합니다. 하나를 만들었다고 나머지가 자동으로 완성되지는 않습니다.
